## ЦЕЛЬ ПРОДУКТА

Сервис превращает посты Telegram-каналов в SEO-статьи, которые индексируются в Google/Яндекс и приводят органический трафик на канал. Монетизация — подписка с владельцев каналов.

**Наше конкурентное преимущество над TGPages:**
- Не одно предложение промта, а многостадийный пайплайн (SERP анализ → LSI → AI-писатель)
- Статья 800-2000 слов (у TGPages — короткое описание)
- Страницы удовлетворяют contentEffort (по DrMax гл. 8) потому что имеют структуру, данные, FAQ

### [P0-1] Sitemap.xml

**Почему критично:** Google не знает о существовании наших страниц. site:post-seo.seo-rezult.ru = 0 результатов. По DrMax гл. 17.1 — sitemap это первичный сигнал для isRoboted и seenNoindex.

**Что делать:**

Создать файл: `frontend/src/app/sitemap.ts` (Next.js 15 metadata)

```typescript
// Динамический sitemap — все is_indexed=true посты
export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const posts = await db
    .select({ channelUsername: channelOwners.channelUsername, seoSlug: channelPosts.seoSlug, updatedAt: channelPosts.updatedAt })
    .from(channelPosts)
    .innerJoin(channelOwners, eq(channelPosts.channelId, channelOwners.id))
    .where(eq(channelPosts.isIndexed, true))
    .orderBy(desc(channelPosts.updatedAt))
    .limit(50000) // Google лимит на sitemap

  return [
    { url: SITE_URL, lastModified: new Date(), changeFrequency: 'daily', priority: 1 },
    ...posts.map(p => ({
      url: `${SITE_URL}/${p.channelUsername}/${p.seoSlug}`,
      lastModified: p.updatedAt,
      changeFrequency: 'monthly' as const,
      priority: 0.8,
    }))
  ]
}
```

Проверка: `curl https://post-seo.seo-rezult.ru/sitemap.xml` должен вернуть XML.

### [P1-5] SEO-аудит канала при регистрации

**Почему критично:** это главная фича TGPages. Они делают аудит при первом контакте с ботом. Пользователь видит ценность сразу. Наш продукт не даёт этого — пользователь добавляет бота, и... ничего ценного сразу не видит.

**Что делать в боте** (при команде /start или после активации канала):

```
📊 Анализирую канал @{username}...

✅ Название: {title}
📝 Постов проанализировано: {N}
🔍 Ключевые темы: {topic1}, {topic2}, {topic3}

📈 SEO-потенциал канала:
• Постов подходит для индексации: {N из M}
• Тематическая концентрация: {high/medium/low}
• Рекомендуемые ключевые слова: {kw1}, {kw2}

🚀 Активирую автоматическую публикацию...
```

**Реализация:**
- После `ch:activate:{channelId}` → запустить worker job `analyze_channel`
- Worker: взять последние 20 постов → Gemini: определить 3 главных темы, ключевые слова
- Результат сохранить в `channel_owners.seo_audit_json`
- Отправить сообщение пользователю через notify-endpoint

**Схема данных:**
```sql

-- { topics: [], keywords: [], indexable_count: N, focus_score: 0.0-1.0 }

### [P1-7] Улучшение contentEffort

**Почему критично:** DrMax гл. 8 — Google LLM оценивает "сложность воспроизведения" контента. AI-генерированный текст без уникальных данных = низкий contentEffort = риск HCS penalty.

**Текущая проблема:** наши статьи — SERP анализ → Gemini → текст. Это паттерн "компиляции из топ-5". LLM-судья Google легко распознаёт.

**Что добавить в pipeline для повышения contentEffort:**

1. **Уникальные данные поста**: включить метрики из самого поста в статью
   - Дата публикации, количество просмотров (если есть)
   - Точные цитаты из поста (это "прямая речь эксперта" = сильный сигнал)
   - Конкретные факты/цифры из поста

2. **Anti-replicability (DrMax 8.4.1)**: многоуровневая аргументация
   - Тезис → контртезис → ограничение → вывод
   - НЕ линейное перечисление фактов

3. **Переменная зона усилия (DrMax 8.4.3)**: разные блоки для разных постов
   - Тип A: "Частые вопросы по теме + данные опроса аудитории"
   - Тип B: "Сравнительный анализ подходов"
   - Тип C: "Практический кейс с результатами"
   - Выбор типа = random(weighted) или на основе темы поста

4. **Явные ограничения (DrMax 8.4.4)**: фразы типа "По данным на {дата}...", "Это актуально для..."

**Промт-инструкция для Gemini:**
```
ОБЯЗАТЕЛЬНО включи:
1. Прямую цитату из поста (в кавычках)
2. Конкретные числа или даты из поста
3. Секцию "Ограничения: эти данные актуальны на [дата поста]"
4. Нелинейную аргументацию: утверждение → контраргумент → вывод
НЕ делай: шаблонные вводные "В современном мире...", "Важно отметить..."
```

### [P2-10] Anti-replicability в шаблоне статьи

**По DrMax 8.4.3**: шаблон → "ядро + переменная зона". Ядро одинаково, переменная зона делает каждую статью уникальной.

**Структура статьи:**

```
[ЯДРО — всегда одинаково]
H1: {seo_title}
Вводный абзац (2-3 предложения из поста)
Прямая цитата из поста

[ПЕРЕМЕННАЯ ЗОНА — выбирается алгоритмически]
Тип 1 (практика): "Как применить на практике" — пошаговое руководство

Тип 3 (история): "Кейс: как это работает" — нарративный формат

[ЯДРО — всегда одинаково]
FAQ-секция (5-7 вопросов на основе PAA из Google)

### [P2-11] Тематические кластеры (Hub and Spoke)

**По DrMax 9.3**: siteFocusScore = насколько все страницы сайта тематически близки к "солнцу" (главной теме).

**Наша архитектура:**

```
HUB: /channel_username/            ← страница канала (обзор всей темы)
SPOKE: /channel_username/slug-1    ← конкретный пост
SPOKE: /channel_username/slug-2    
SPOKE: /channel_username/slug-3
```

**Что сделать:**
- Страница канала (`/{username}`) должна ссылаться на ВСЕ статьи канала
- Каждая статья должна ссылаться обратно на страницу канала (entity-first linking, DrMax 9.5.4)
- Анкор не обязан быть точным: "другие материалы по теме {topic}" → EntityAnnotations распознает связь

## СЕКЦИЯ 5. ПОНИМАНИЕ ПОЧЕМУ СТРАНИЦЫ НЕ ИНДЕКСИРУЮТСЯ

По DrMax гл. 18.2 "Цикл качества":

**Текущий отрицательный цикл:**
1. Нет sitemap → Google не знает о страницах
2. Google не знает → нет показов → нет кликов
3. Нет кликов → NavBoost не видит сигналов
4. siteAuthority = 0 (новый субдомен)
5. Страницы не попадают в выборку Mustang

**Запуск положительного цикла:**
1. Sitemap + GSC → Google находит страницы
2. Страницы с высоким contentEffort → Mustang пропускает
3. Показы → клики → NavBoost накапливает goodClicks
4. siteAuthority растёт → новые статьи легче индексируются

**Критически важно:** первые 10-20 проиндексированных страниц определяют репутацию домена. Они должны быть максимально качественными. Лучше 10 отличных, чем 100 шаблонных.

## СЕКЦИЯ 7. QA-СЦЕНАРИИ ДЛЯ АГЕНТА

Сценарии для автоматической проверки бота через Playwright/API:

### Сценарий 1: Полный онбординг
1. Написать /start боту
2. Проверить: получили инструкцию по добавлению
3. Симулировать добавление бота в канал (через реальный тестовый канал)
4. Нажать "Проверить — бот добавлен"
5. Ожидать: ✅ активирован + SEO-аудит канала

### Сценарий 2: Автопубликация
1. Опубликовать пост в тестовом канале
2. Ожидать: через N минут (autoPublishDelay) — статья создана в БД
3. Ожидать: URL статьи открывается (200 OK)
4. Ожидать: через 5 мин — Telegram уведомление "✅ SEO-статья опубликована"
5. Проверить: is_indexed = true в БД

### Сценарий 3: Фильтры списка постов
1. Открыть список постов (фильтр: "Все")
2. Проверить: показываются все посты
3. Переключить на "Опубликовано"
4. Проверить: показываются ТОЛЬКО is_indexed=true посты
5. Переключить на "Ожидают"
6. Проверить: показываются ТОЛЬКО is_indexed=false + status=pending

### Сценарий 4: Ручная публикация
1. Перейти к конкретному посту (filter=pending)
2. Нажать "Продвинуть в SEO"
3. Ожидать: статус изменился на "processing"
4. Ожидать: через 2-3 мин — уведомление готово
5. Проверить: статья на сайте открывается

### Сценарий 5: Настройки канала
1. Открыть "Настройки"
2. Переключить "Автопубликация" (ON/OFF)
3. Изменить задержку (0 → 60 → 120 → 0)
4. Проверить каждое изменение в БД

### Сценарий 6: SEO-аудит при активации
1. Зарегистрировать новый канал
2. Добавить бота
3. Нажать "Проверить — бот добавлен"
4. Ожидать SEO-аудит в ответ
5. Проверить: в channel_owners.seo_audit_json данные появились

### Сценарий 7: Paginator
1. Добавить 10+ постов через тестовый канал
2. Проверить страницу 1 (3 поста)
3. Нажать "Вперёд →"
4. Проверить страницу 2 (следующие 3)
5. Проверить крайние случаи: первая страница (нет кнопки "Назад"), последняя (нет "Вперёд")

### Сценарий 8: Ссылки в уведомлении
1. Создать пост с seo_slug
2. Получить Telegram уведомление
3. Проверить: кнопка "🔗 Открыть статью" ведёт на корректный URL
4. Открыть URL — страница отдаёт 200

### Сценарий 9: Переключение каналов (если >1 канал)
1. Зарегистрировать 2 разных канала
2. В боте переключиться между ними
3. Проверить: список постов соответствует выбранному каналу

### Сценарий 10: Удаление канала
1. Открыть настройки канала
2. Нажать "Удалить канал"
3. Подтвердить
4. Проверить: редирект на /dashboard
5. Проверить: данные канала удалены из БД
6. Проверить: страницы постов отдают 404

## СЕКЦИЯ 8. ТЕХНИЧЕСКИЕ РИСКИ

| Риск | Вероятность | Последствие | Митигация |
|---|---|---|---|
| HCS penalty за AI-контент | Средняя | Понижение всех страниц | Улучшить contentEffort (P1-7) |
| Sitemap слишком большой | Низкая (>50k URL) | Google игнорирует часть | Пагинация sitemap |
| Subdomain vs domain | Средняя | Медленный рост siteAuthority | Рассмотреть переезд на основной домен |
| pandaDemotion за "тонкий" контент | Низкая | Весь сайт в штопоре | Контроль качества на pipeline уровне |
| BullMQ job failures | Средняя | Посты не индексируются | Мониторинг + dead letter queue |
